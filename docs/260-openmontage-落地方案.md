# 260 · OpenMontage 借鉴点 → Lumo 落地方案（2026-11-21）

> 承接 259 的借鉴清单。只落「最值得抄、且 Lumo 缺」的 3 个点，每点给 MVP → 进阶两档。

## 一、检索式真视频素材（Retrieval-first B-roll）★ 首选

**现状**：Lumo 的视频全走算力汇生成（Seedance），没有「真实镜头素材」能力。
**借鉴**：OpenMontage 用 CLIP 索引 17 个免费素材库，语义检索真实运动镜头做 B-roll。

### MVP（先跑通关键词检索）
1. 接 **Pexels API**（免费、有视频、无需鉴权重）+ **Pixabay**（备选）。
2. 在 Toonflow 画布加一个「**真实素材检索**」节点：输入主题/关键词 → 返回镜头列表（缩略图 + 时长 + 分辨率）→ 用户勾选 → 拖入时间线。
3. 复用 Toonflow 已有的下载/转码能力（ffmpeg）把选中镜头转成工作区素材。

### 进阶（语义检索）
1. 对本地已下载的素材建立 **CLIP 索引**（`clip_embedder` 思路），存向量。
2. 检索时语义排序（`scoring` 思路），支持「找一个傍晚海边的空镜」这类自然语言。
3. 素材源扩到 Archive.org / NASA / Wikimedia（都是公开可商用或 CC 许可）。

**落点**：Toonflow 新增一个 `videoSourceNode`（或并入现有素材面板）。MVP 工作量 ≈ 1 个节点 + 1 个 Pexels 客户端。

## 二、流水线清单 + 导演技能（升级「一键成片」）

**现状**：Toonflow 有 AI 助手 + 剪辑，但「一键成片」是半自动，流程不透明、不可控。
**借鉴**：OpenMontage 的流水线 = YAML 声明（阶段 → 技能 → 产出物 → 评审焦点 → 成功标准），每阶段一个 markdown「导演技能」。

### 落地方案
1. **定义一条「短剧成片」流水线清单**（JSON，仿 OpenMontage 的 pipeline_defs）：
   ```
   剧本 → 分镜 → 白模预演 → 生成(图片/视频) → 剪辑 → 成片
   ```
   每阶段：`skill`（导演技能）+ `produces`（产出物）+ `review_focus`（评审焦点）+ `success_criteria`（成功标准）+ `checkpoint`（检查点）。
2. **把生产 know-how 编码成「导演技能」**（markdown），放进 Toonflow 的 **Skill Hub**（已有）：剧本导演 / 分镜导演 / 剪辑导演 / 合成导演。
3. **创作助手按流水线执行**：读清单 → 逐阶段读技能 → 调用已有节点/工具 → 写检查点 → 自审 → 关键点人工确认。

**落点**：Toonflow 的 AI 助手（已有 agent + Skill Hub）之上加一层「流水线清单 + 阶段检查点」。不新造轮子，复用 Toonflow 的节点/Skill 体系。

## 三、成本治理 + 评审门（接算力汇后实用）

**现状**：Lumo 生成有成本（算力汇按秒/张计费），但没有预算控制和阶段确认。
**借鉴**：OpenMontage 的 `cost_tracker`（estimate→reserve→reconcile）+ 每阶段 `human_approval` 门。

### 落地方案
1. **生成前成本预估**：复用已实现的 `getPrice`（算力汇倍率价格表），在生成按钮旁显示「预计 ¥X」。
2. **预算上限**：设置里加「单次生成上限 / 每日上限」，超限拦截（仿 estimate→reserve）。
3. **阶段评审门**：在「一键成片」流水线的关键节点（脚本定稿、分镜定稿、成片导出前）加确认弹窗。

**落点**：Toonflow 的生成节点 + 设置面板。工作量小（都是 UI + 校验逻辑）。

## 四、优先级与依赖

| 顺序 | 项 | 依赖 | 工作量 |
|---|---|---|---|
| 1 | 检索式真视频素材（MVP）| Pexels API key | 中（1 节点）|
| 2 | 成本预估 + 预算上限 | 已有 getPrice | 小 |
| 3 | 短剧成片流水线 + 导演技能 | 已有 AI 助手 + Skill Hub | 中 |
| 4 | 检索式真视频素材（CLIP 进阶）| MVP + 向量库 | 大 |

**建议顺序**：先 2（成本预估，小且刚需）→ 再 1（真实素材，差异化）→ 再 3（流水线，复用已有）。
